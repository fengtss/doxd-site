Feng Privacy Policy

Last updated: October 14, 2026

This policy explains how Feng processes information while providing Discord bot features.

1. Data Feng processes

Depending on the features used, Doxd may process Discord account, server, channel, role, message, attachment, reaction, voice-state, moderation, command-use, ticket, reminder, giveaway, XP, nickname and username history, birthday without birth year, timezone, highlight, Last.fm, Spotify, and configuration data. This can include Discord IDs, timestamps, usernames, display names, avatars, message text, message links, and moderator-provided reasons.

Optional integrations process only the identifiers, authorization records, and response caches needed for the requested integration. Doxd does not sell Discord API data.

2. How data is used

Feng uses this information to provide server configuration, moderation and security enforcement, logging, tickets, reminders, music, utility commands, personalization, and explicitly enabled third-party integrations. Doxd does not use Discord API data for advertising or unrelated profiling.

3. Retention

  • Bounded in-memory snipes, edits, reactions, anti-spam windows, and request caches disappear on restart or when the relevant privacy deletion command runs.
  • Last.fm response cache entries are retained for no more than 7 days.
  • Reaction-message tracking entries are retained for no more than 3 days.
  • Completed privacy requests are retained for 90 days; pending requests remain until resolved.
  • Audit and name-history records are retained for no more than 365 days.
  • Rotated encrypted runtime logs and encrypted historical runtime-log archives are retained for no more than 30 days.
  • Active feature data is retained while required for that feature, until removed through its command, the privacy workflow, or server removal.
  • Encrypted database backups are retained for no more than 30 days after a newer authenticated replacement exists. If no verified replacement exists, the newest recovery copy may remain beyond 30 days until a replacement passes authentication and recovery checks; the retention worker records this exception.

Messages, attachments, and transcripts sent to a Discord channel remain subject to that server's Discord permissions and retention choices.

4. Access, correction, and deletion

Users can run the following commands:

  • ,privacy export to receive a private JSON inventory by direct message.
  • ,privacy correct (details) to submit a correction request.
  • ,privacy status to review recorded requests.
  • ,privacy delete DELETE MY DATA to delete direct records, scrub references from shared records, remove linked-provider caches, and clear bounded in-memory records associated with the requesting Discord account.

Exports redact access tokens, refresh tokens, client secrets, and other credentials. Prefix-command exports are never posted publicly.

5. Sharing and service providers

Data is sent to Discord and a selected integration provider only when needed for the feature a user invokes. Hosting and infrastructure providers act as service providers for operating Doxd. Information may also be disclosed when required by law or needed to investigate abuse or a security incident.

6. Security

Feng uses application-encrypted database storage, protected credentials, authenticated encrypted log and backup artifacts, restricted service access, and fail-closed startup checks. No online service can guarantee absolute security.

7. Incidents and policy changes

The operator will investigate suspected unauthorized access, begin remediation, notify Discord and affected users when required, and preserve only the evidence needed for that response. Material changes to data collection, purpose, sharing, or retention will be reflected here.
